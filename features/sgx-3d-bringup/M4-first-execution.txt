DIAGNOSIS (2 issues):
1. USE_CODE_BASE(15) encoding: code at VA 0xf8000000 but 25-bit ADDR field holds
   0xf8000000 & 0x01FFFFFF = 0, so USSE fetches at VA 0 -> fault_addr=0x0. Fix:
   map ukernel code at a device VA < 32MB and write that to USE_CODE_BASE.
2. MMU context: BIF dir1(ctx1/pf_pd)=0 (not programmed); active context is
   dir0=0x34a6f000 (default pd). Code mapped in pf_pd may be invisible to the USSE.
   Likely fix: map ukernel BOs into the ACTIVE context (default pd) or ensure ctx1
   is programmed and the USSE runs in it.

--- UPDATE: microkernel EXECUTES (init scripts + all fixes) ---
After implementing the full DDK init scripts (Part1 clkgate + Part2 34 regs),
USE_CODE_BASE=(base>>7)|(DM3<<25), PDS_EXEC_BASE=0xF6000000, KERNEL_DATA-heap
buffer placement: the USSEPDS fault_addr=0x0 is ELIMINATED. Diagnostic after
the boot EVENT_KICK:
  EDMTask0[0xB10]=0x10000 EDMTask1[0xB1C]=0x10000  (ukernel advanced its task regs)
  EVENT_STATUS=0 (event consumed), CLKGATE=0x1111111
  host_ctl: only our own service-addr patches at 0x2c-0x3c; ukernel wrote nothing.
=> microkernel runs its event handler but does not complete init (writes no
INIT_COMPLETE) because its internal PDS/data pointers are un-relocated 0xdbeef
placeholders. INIT_COMPLETE requires the closed microkernel relocation format,
not recoverable from the available EMGD binaries. This is the boundary.
